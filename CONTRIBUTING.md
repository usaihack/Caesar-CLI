# 👋 Contributing to Caesar CLI

Thank you for your interest in contributing to **Caesar CLI**! We ❤️ open-source contributions.

This document provides a set of guidelines to ensure the collaboration process is smooth and consistent for everyone.

---

## 🛠️ How to Contribute

### 1. **Fork the Repository**

Click the **Fork** button at the top right of the repository page to create a copy of the project in your own GitHub account.

### 2. **Clone Your Fork**

```bash
git clone https://github.com/usaihack/Caesar-CLI.git
cd Caesar-CLI
```

### 3. **Create a Feature Branch**

Create a new branch for your feature or bug fix:

```bash
git checkout -b feature/AmazingFeature
```

### 4. **Make Your Changes**

- Write clean, efficient code.
- Ensure your changes do not break existing functionality.
- Add comments where necessary.

### 5. **Commit Your Changes**

Use a clear and descriptive commit message:

```bash
git commit -m "Add some AmazingFeature"
```

### 6. **Push to Your Fork**

```bash
git push origin feature/AmazingFeature
```

### 7. **Open a Pull Request (PR)**

- Go to the original repository on GitHub.
- Click **"Compare & pull request"**.
- Provide a clear title and description of your changes.
- Reference any related issues.

---

## 🐞 Issues and Bugs

If you find a bug or have a suggestion, please check the [Issue Tracker](https://github.com/usaihack/Caesar-CLI/issues) first to see if it has already been reported.

If not, feel free to open a new issue with:

- A clear title.
- A detailed description of the problem.
- Steps to reproduce (if applicable).
- Screenshots or logs (if applicable).

---

## 🧑‍💻 Code Style

- Follow standard **Python PEP 8** guidelines.
- Keep the code modular and readable.
- Use meaningful variable and function names.
